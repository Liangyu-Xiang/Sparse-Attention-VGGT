# 修订版逐层共享 A/V 方案与实验结论

状态：**已实现、完成实验，但精度和速度均未达标，仅保留为显式选择的实验配置。**

## 最终实现

- 稀疏化 VGGT 的全部24个 global attention 层，索引0–23；原有帧内/local attention 不变。
- 一层只维护一套细簇、Mask 和历史，不做逐头策略或跨层头匹配。真实注意力仍使用各头自己的 Q/K/V。
- 第0层按每帧二维 patch 网格均匀划分，代表 token 固定为空间位置，不进行任何 Value 驱动的聚类更新。28×37 patch 网格对应11×14细格、2×4粗格。
- 后续层只继承细簇标签和代表索引：用当前层平均 V 重选代表，构建当前临时粗簇，做一次带锚点的同步局部重分配，再更新代表并重建最终粗簇。不继承粗簇。
- 细簇代表采用 centroid-nearest 真实 token；粗分组采用2次轻量 Lloyd。不是精确 PAM/k-medoids，也不构造 token 两两距离矩阵。
- 对原模型 normalization、RoPE 之后的 Q/K 先平均所有头，再用当前 Value 粗簇池化 K，计算一张逐层共享的粗注意力。没有另一套 Key block，也没有 Query 共用 Mask 的路由块。

## 比例判断与边预算

均匀确定性采样0.25%的 Query，仅用来判断本层属性。对于实际输入的133248个 Query，采样334个。

设采样得到的粗注意力分布为 P：

1. C = 1 − 平均注意力熵 / log(粗簇数)，表示集中程度。
2. D = 1 − 平均 cosine(P_i, 所有采样 Query 的平均分布)，表示 Query 差异。
3. 原始 Attention 偏好为 α = 2CD / (C+D+ε)。
4. 阈值 τ=0.95：α≤0.05 时转为 Value-only，α≥0.95 时转为 Attention-only，其余保留连续比例。

本轮额外校准了一个**全层共用的粗 QK 倍率32**，仅作用于粗注意力，不改变真实稀疏注意力的温度。这是显式调参扩展；未加倍率的聊天原公式也保留为基线。没有按层号强制设置 A/V 比例。

每个 Query 最终保留 floor(0.1×全部Key数) 条边，强制特殊 Key 也计入这10%。128帧时共有133248个 token，每个 Query 保留13324个 Key，其中640个是特殊 Key、12684个为 patch Key，实际保留率9.99940%。

在12684个 patch slots 内，KA=round(α×12684)，KV=12684−KA。

## 选边与历史

先依据每个 Query 的当前粗注意力分配 KA，采用容量约束的最大余数舍入；再执行“历史复用 → 细簇代表探索”。历史按 **token** 去重，不能强制同一当前细簇只留一条已经验证的 Attention 边。

每个 Query/粗簇的可用容量为：细簇数 + 历史 token 数 − 历史覆盖细簇数。这样可以保留多个真实高权重历史 token，缺额仍只用未覆盖细簇的代表补齐，不随机塞入未经验证的成员。

随后，Value 分支从 Attention 尚未覆盖的细簇中，按 population 选择 KV 个代表。最终 Mask 每个 Query 独立、所有头共享。

真实 sparse attention 只计算最终支持。一次 QK 同时导出 logits 与包含特殊 Key 的 per-head LSE；用 softmax 后的各头注意力权重平均，从整个实际支持中选 top-KA patch edges 写入下一层历史。Value 边也可以被提升。不是平均 logits，也不会额外重算一遍 QK 来验证。

Value-only 计算完采样统计即跳过 full-query coarse QK、逐 Query 路由和历史验证，使用共享代表 K/V 的 SDPA。没有稠密探针、总预算自适应、Dense fallback。

## 工程修正与验证

- Mask/attention 内存 chunk 为1024；粗 QK 采用独立、固定的128行算术分块，避免不同 GEMM 形状的浮点差异破坏配额和跨层状态。这不是 Query 共享 Mask。
- 已在真实128帧输入上验证：τ=0.9 时，第0–6层的输出、细簇、代表和历史在 chunk128/1024 下逐字节一致。此检查不等于最终 τ=0.95 下完整24层的双 chunk 位姿检查。
- 完整测试218通过、1跳过。最终配置在每场景1次预热、3次正式前向中位姿完全一致；Chess 的最终位姿还逐字节复现了同配置的单次校准结果。
- 所有版本的源码快照、哈希、输入路径、逐层 C/D/α、实际预算、分支模式和计时均分开保存。被否决的旧约束版本、数值不等价版本及中止版本不混入最终统计。

## 超参选择

最终配置：细簇比例约15%、粗簇目标128个原始 token、Query 采样0.25%、粗 QK 倍率32、单分支阈值0.95。

先进行了离线信号筛选及若干单参数检查，随后在正确实现上对倍率{16,32,64}×阈值{0.8,0.9,0.95}做了9组 Chess 联合校准。选择时要求外围区段 Value 占多数、中段 Attention 占多数，再比较 Chess 位姿 AUC；没有使用其余六场景选取这组参数。

倍率16/阈值0.95的 Chess AUC30略高，但中段 Attention 只有31.67%；倍率32/阈值0.95为83.97%，中段52.15%，因此选择后者。不能称其为全局最优；最终配置的采样率没有重新做完整独立消融。

## 最终结果：7Scenes，每场景均匀128帧

下表为零基索引，比例是 **patch slots 内的实际分支占比**，是区段均值，不代表每层均满足主导关系。

| 区段 | Attention | Value |
|---|---:|---:|
| 3–9 | 14.83% | 85.17% |
| 10–16 | 50.24% | 49.76% |
| 17–23 | 4.93% | 95.07% |

区段差异形成，但中段远非100% Attention，独立六场景的中段 Attention 均值甚至只有49.92%。没有任何场景/层进入 Attention-only；25.60%为Value-only，其余74.40%仍为Mixed。

位姿 AUC30：

- 七场景均值60.29%；其中 Chess 用于调参。
- 排除 Chess 的独立六场景均值56.34%。
- Chess83.97%，但 Fire仅1.74%，存在严重失败场景。
- 聊天原公式基线七场景33.32%；同输入的历史 Dense84.29%、SAF3R84.58%为准确率参考，不用于当前严格计时比较。

最终配置完整前向耗时：七场景的“各场景3次正式前向中位数”再平均为99.07s，其中 global attention 为93.50s。

另对 Chess 做了同输入、同预热/重复设置的完整成本重测：

| 方法 | 完整前向 | Global attention |
|---|---:|---:|
| Dense | 16.73s | 11.17s |
| SAF3R | 10.75s | 4.84s |
| 本方案 | 95.65s | 89.94s |

SAF3R每次正式前向都重新构建 lazy Top-K，未复用预热缓存；它采用原 profile/topk128-per-frame，不是统一10%预算。A/V与基线来自独立运行，不是随机交错测量。

最后一次正式前向的分段计时均值中，Value层级更新（含norm/RoPE）约1.36s、采样统计约0.08s，选边＋indexed attention＋历史验证合计约91.97s。这三者尚未分别隔离，不能断言其中单一算子独占开销；也不能将最后一次分段计时之和等同于3次中位数。

**结论：比例拟合不等于保留模型质量，保留10%边也不等于实际加速。本轮实现与实验已完成，但未获得可用的加速方案；不替换原有默认方法。**
