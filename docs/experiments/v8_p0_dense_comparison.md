# Original Dense versus v8 sparse execution: runtime and quality diagnosis

The exact starting source is frozen v8 on99bbb99b. The main shared checkout and other optimization worktrees were not edited. This independent branch contains opt-in helpers, separate commits for packing and state loss, and rejection evidence. Original Dense/SAF3R quality controls remain unchanged.

The user explicitly requested a fresh original-model forward/core comparison. Native Dense, v8, initial P0 and beta were therefore measured sequentially on physical GPU7 with the exact heads128 input/checkpoint and one warmup+three complete forwards. Each subprocess holds a CPU-only lock until full exit; no auxiliary CUDA context. Full results, disjoint accounting, all24 layer timings and raw exclusivity monitors are in [the comparison report](../../outputs/dense_sparse_comparison_20261104/report.md).

The full-forward medians are Dense12.480868s, v820.525772s, initial P020.806060s and beta19.798294s. Beta samples range19.378833–22.849094s, so precision must not be inferred from displayed decimal digits. Historical19.553523s beta timing belongs to an earlier batch. The separate profile measures Dense core7.562792s and v8 fused sparse core6.462369s. Full model is slower because saved core time is far smaller than added routing/history work. A same-QKV first-window experiment over24 layers finds1.615x core and1.384x executor ratios; these are sampled operators, not full-forward speedups.

Common QKV/Norm/RoPE/projection is0.519506s Dense and0.519980s v8. The backbone/frame Attention/FFNs/heads are present in BOTH models. Added sparse work includes Value geometry, coarse/history observation, prior estimation, state losses/selection, support packing, transfer weights, statistics and sorting/gathers. It is incorrect to call the entire3–5s outside-global residual an added sparse cost, or to estimate Dense core by subtracting a sparse residual from a historical full-model measurement.

The beta regression diagnosis fixes identical Q/K, support and coarse observations on the beta trajectory. At L1 the new prior assigns old support0.784330 mass, exact Dense0.196463, shadow v80.223279. It uses compensated sparse mass as an individual-Key prior and hard-clamps unselected Grid mass to zero. Sampled zero-prior fraction7.9149%, selected zero-prior fraction1.5635%. Existing weight=assigned/max(own,1e-30) then reaches log-bias61.2362. About98.4365% of valid per-probe sparse probabilities fall below FP16 rounding-to-zero threshold, while shadow v8 conditional cache has no zeros. Thus probability semantics, zero-prior compensation and cache dynamic range form a directly observed feedback chain. The diagnostic does not uniquely isolate every causal contribution through a new full-dataset intervention. No probability floor, retention, confidence or quality threshold was tuned on test truth. Same-support/bias FP32 checks show only small sampled execution errors, not gross wrong-mask behavior.

## Stronger equivalence result

The later ALL-window oracle found a Key mismatch at L1 beyond the first sampled window, even after preserving original tile size. Therefore the first-window pass above must not be read as a complete equivalence pass. The corrected P0 prototype is also NOT accepted as a globally equivalent replacement. The all-window failure and first-mismatch investigation are retained. Its already-authorized18-scene evaluation records this rejected candidate's actual quality; it is not a reason to relax the equivalence requirement or promote it.
