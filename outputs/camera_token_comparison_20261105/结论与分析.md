# Camera token 逐层诊断结论

本次保持 A＋全特殊 token 修正＋20% 簇数不变，仅增加观测。ETH3D 沿用既有 filtered11 场景、377 帧；三种方法使用相同 checkpoint、完整输入列表、预处理。只使用 GPU4/5/6。检查了 24 个帧内块和 24 个全局块的全部 16 个头及全部 camera Queries，没有对 Key 做诊断抽样。

**核心发现：camera Query 已经使用完整 Key/Value；主要偏移来自此前稀疏计算改变了输入特征，特别是中后层的 Value。当前证据定位了误差传递路径，还不能证明它解释了全部 AUC 损失。**

1. 同一 Q/K/V 下，将实际 camera 输出与 Dense 算子比较，我们的方法最大相对 L2 为 0.002724，Dense 自身 FP32 重建的最大差异为 0.002866；属于相同数量级的 BF16/FP32 数值误差。所有方法的实际输出重建误差均低于 0.003490。没有发现 camera Query 的稀疏支持集遗漏。
2. 全局块输出的 camera 相对 L2 在第12层为0.01815、第16层0.05694、第17层0.08654、第18层0.16366。第17层全局块输出到第18层全局块输入之间还经过第18个帧内块，误差由0.08654升至0.13280；随后第18个全局块输出达到0.16366。因此需要同时检查帧内传播，不能把全部增长归于一个全局注意力算子。
3. 第16/17/18个全局层的 patch Value 相对 L2 分别为0.43477/0.50415/0.41651，显著大于 camera Query 的0.04143/0.05643/0.07640。第18层只替换当前 V，投影后输出相对 L2 为0.27711；仅当前Q为0.01009，仅当前K为0.03993，当前QK＋Dense V为0.04127，完整当前QKV为0.28584。这里 V 包括全部 token，不能仅凭此数将全部误差量归于 patch。各项非线性且不能相加为贡献率。
4. 相机头输入的场景等权均值：我们 cosine=0.987842、relative L2=0.148085；SAF3R cosine=0.986025、relative L2=0.158584。我们在7/11场景相对L2更低，但 delivery_area、relief_2、relief、pipes 更高。整体平均余弦或L2不能替代位姿精度。
5. SAF3R 的 camera 注意力在若干头使用首帧、帧内、stride 等限制，分布可以明显偏离 Dense，但其最终特征仍可接近 Dense。这说明强行让注意力概率更接近 Dense 并不能保证更好的位姿。SAF3R broadcast_first 的打分Q/K来自首帧、V来自目标帧；图中按实际 Value 来源表示注意力，原始数据另存打分Key来源，避免误读。
6. 相机头迭代会改变误差方向和大小；我们第2次迭代的第2块达到0.30170，但最后一块为0.10669。不能笼统表述为误差一直放大，更不能把这些中间特征差异直接解释为AUC。

第16–18层是patch Value偏移陡增的起点，不是唯一敏感区域。后续第20层完整当前QKV输出误差达到0.49140，第23层为0.45684；仅当前V的曲线同样较高，完整曲线见qkv_counterfactuals.png。
## 对后续修复的指向

优先方向是保护对 camera 输出有作用的 Value/patch 信息，在现有预算内调整状态选择或层间预算，而不是再给 camera Query 增加 Key。第16–18层是优先排查区域；第18层的上游帧内块也在范围内。本次没有改变稀疏率、损失、路由、内核或任何生产参数，也没有开展速度牺牲型修复。若后续修改，仍需用匹配的完整前向计时与六项精度验证；这些诊断本身不能承诺AUC提升。
